# iPhone Duo

[한국어](SKILL.md) | [English](SKILL.en.md) | 日本語

単一の `iphone-duo` スキルの日本語版です。SwiftUI・UIKit アプリの Duo 対応として、適応型レイアウト、垂直バー、ヒンジ、複数 scene、カメラ切り替えを調査・実装します。Duo 対応の依頼や開閉に伴う UI・状態・カメラの問題に使用します。一般的な iOS 作業で回転に言及しただけでは適用しません。

ガイドは1言語だけ読み、その言語の必要な参照のみ追加で読みます。各言語版は同期して更新し、この翻訳を別スキルとして登録しません。

既存アプリの構造と対応 OS を尊重しながら、サイズ・姿勢・ディスプレイの変化に適応させます。説明と結果はユーザーの言語で書き、API 識別子は原綴りを維持します。

## 作業開始

1. プロジェクトの指示と既存の変更を読み、SwiftUI/UIKit、デプロイ対象、ビルド方法、対象画面、状態の所有者を把握します。レビュー依頼では指摘を報告し、実装依頼では修正と検証まで進めます。
2. `xcodebuild -version`、`xcodebuild -showsdks` で実際の環境を確認します。シミュレータ検証が必要なら `xcrun simctl list devices available` で対象を探します。存在しない Duo runtime や destination を仮定しません。
3. 新 API の導入前に [SDK 確認](references/ja/compatibility.md)を読みます。発表資料に登場する API と、現在の SDK でコンパイルできる API を区別します。
4. 依頼された機能に必要な参照だけを読みます。カメラや複数ウインドウを必要としないアプリに、それらを追加しません。

## 実装原則

- 機種名や `.phone`/`.pad` から空間を推定せず、現在のコンテナのサイズと size class を使います。size class だけでは表せない最小コンテンツ幅は、実際の利用可能幅で判断します。
- `UIScreen.main.bounds` による UI サイズ計算は、対象の view/scene 基準に置き換えます。画面オブジェクトが必要なら接続された window scene から取得します。
- safe area と margins の四辺を個別に扱います。背景の拡張と操作要素の配置を分けます。
- 標準 navigation container とシステムバーを優先します。既存のカスタムデザインの目的を確認し、必要な箇所だけ調整します。
- サイズ変更で navigation path、選択、編集中の内容、再生位置を初期化しません。共有ドメインデータとウインドウごとの UI 状態を分けます。
- デプロイ対象を独断で引き上げません。使えない API は既存レイアウトで代替し、新機能は SDK で確認してから統合します。

## 完了報告

変更した画面・ファイル、ユーザーから見た動作の変化、実行したビルド・テストと結果、未確認の機種固有動作を要約します。静的な調査や通常の iPhone シミュレータでのテストを、Duo 検証の合格として報告しません。実装依頼では可能な修正を完了し、環境が理由で保留した部分だけ具体的に残します。
