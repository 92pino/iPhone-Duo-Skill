# ナビゲーションとバー

[한국어](../bars.md) | [English](../en/bars.md) | 日本語

SwiftUI は navigation container の toolbar、UIKit は navigation/tab controller を優先します。バーを手動で回転したり固定の側面余白を足したりしてシステム動作を再現しません。

## 項目ごとの判断

- ボタンには意味のあるタイトルとアイコンを渡します。SwiftUI の `Label` のようにシステムが表示方法を選べるようにします。
- 金額や進捗のようにテキスト自体が情報なら、アイコンだけにしません。単純な件数はバッジにできますが、アクセシブルな名前でも意味を伝えます。
- 戻る/閉じる、主要操作、補助操作の順を確認します。サイズが変わっても同じ操作を提供し、必要なら overflow から使えるようにします。
- キーボード、長い翻訳、大きい文字でも主要操作が失われないか確認します。キーボード accessory はキーボードに付随させます。
- 内側ディスプレイが縦向きのときは HIG 上の例外で、標準の横バーを維持できるだけの縦方向の余白があります。すべての姿勢で垂直バーに強制的に切り替えません。
- Split View マルチタスキングで内側ディスプレイを左右に分けて使うとき、各アプリは自分の外側の端にコントロールを配置します(左のアプリは左、右のアプリは右)。相手アプリのコントロールと重ならないよう safe area を確認します。

原版の軸制御、表示優先度、overflow 統合、垂直バー無効化の API は [SDK 確認](compatibility.md)後に適用します。custom bar を標準に置き換えると製品デザインが崩れる場合は、まずリサイズ対応とアクセシビリティを改善します。単一ボタンのシートなどで垂直バーを無効にするかは、実際の利用可能空間を比較して決めます。

水平/垂直の切り替え、低い高さ、RTL、VoiceOver の名前と順序、Reduce Transparency を検証します。RTL だからといってシステムバーの物理的位置を手動で反転しません。
