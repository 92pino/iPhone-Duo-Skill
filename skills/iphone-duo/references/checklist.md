# 마이그레이션과 검증

한국어 | [English](en/checklist.md) | [日本語](ja/checklist.md)

해당되는 항목만 실행하고 결과는 통과 / 실패 / 미실시 / 해당 없음으로 기록한다. SDK가 없다는 이유로 가능한 일반 적응형 UI 개선까지 중단하지 않는다.

## 구현 전후

- [ ] 프로젝트 지침, 기존 변경, scheme, 배포 대상, 실제 SDK를 확인했다.
- [ ] 기존 빌드 결과와 변경 후 결과를 비교해 기존 오류와 회귀를 구별했다.
- [ ] 화면 전체 크기·기기 종류 가정과 비대칭 inset 계산을 점검했다.
- [ ] 새 API의 모듈·시그니처·availability와 구 OS fallback을 확인했다.
- [ ] 크기 변경 후 navigation path, 선택, 입력 초안, 스크롤·재생 위치가 유지된다.

## 관찰할 동작

| 상황 | 확인 |
|---|---|
| 좁은/넓은 폭, 낮은 높이 | 잘림·겹침·과도한 빈 공간, 주요 동작 접근 |
| Duo 개폐·부분 접힘·회전 | 조작 요소 가림, 상태 유지, 반복 전환 안정성 |
| 멀티태스킹 좌/우·리사이즈 | 비대칭 safe area, 현재 창 기준 좌표 |
| 키보드·시트·팝오버 | 입력과 완료/취소 동작 접근, anchor 유효성 |
| 큰 Dynamic Type·긴 번역·RTL | 읽기와 탐색 순서, 잘린 텍스트 |
| VoiceOver·Reduce Motion/Transparency | focus 유지, 조작 이름, 가독성 |
| 일반 iPhone·지원 iPad·최저 지원 OS | 기존 화면과 fallback 회귀 |
| 해당 앱의 다중 창·외부 화면 | 상태 독립성, 연결 해제와 요청 실패 |
| 해당 앱의 카메라 | 거부·중단·복귀·개폐·녹화, 저장 결과 방향 |

사용할 수 있는 simulator/실기기에서 대표 사용자 흐름을 실행한다. Duo가 없으면 일반 기기 리사이즈는 부분 검증으로 표시한다. screenshot만으로 상태 유지나 접근성 검증을 대체하지 않는다.

회귀 위험이 있는 상태 전환이나 fallback에는 행동을 검증하는 테스트를 추가한다. 문구·구현 구조를 그대로 비교하는 테스트를 만들지 않는다. 변경과 관련된 기존 테스트 및 빌드를 실행한다.

## 결과 형식

- 변경: 파일과 동작, 변경 이유
- 확인: SDK / scheme / destination / 실행 명령 / 결과
- 미실시: 장치나 runtime 등 부족한 조건과 재현 절차
- 후속: 미확인 API 또는 실패한 검증에 필요한 구체적인 조치
