# iOS 27 Migration

[한국어](SKILL.md) | [English](SKILL.en.md) | 日本語

既存 SwiftUI・UIKit アプリの iOS 27 SDK ビルドと実行時の互換性を調査し、確認した API・動作の回帰を修正して検証します。iOS 27 移行、更新後のエラー、互換性レビューで使用します。新機能の導入や Duo 固有の開閉・複数画面設計は対象外です。

ガイドは1言語だけ読み、ユーザーの言語で報告します。翻訳は別スキルではなく、3言語を一緒に更新します。

## 対象範囲

レビュー依頼では根拠と指摘を報告し、修正依頼では可能な変更と検証まで完了します。機能追加、UI 全面改修、一括依存更新、最低対応 OS や Swift 言語モードの変更を標準作業に含めません。既存の対応範囲、データ、ユーザーフローを維持します。

## 1. 基準環境の確認

- プロジェクト指示と作業ツリーの変更を読み、workspace/project、scheme、アプリ・extension・テスト target、デプロイ対象、依存 lockfile、CI ビルド方法を確認します。
- `xcodebuild -version`、`xcodebuild -showsdks`、`xcrun swift --version` を記録します。必要なら `xcrun simctl list devices available` で runtime と destination を探します。
- **旧 SDK でビルドしたアプリを iOS 27 で実行すること**と、**iOS 27 SDK で再ビルドしたアプリの実行**を区別します。SDK に依存する動作変更と OS 自体の変更を混同せず、各結果に Xcode/SDK/OS build を記録します。
- 変更前の関連ビルド・テストを実行するか、既存 CI の証拠を確認します。失敗が既存か記録し、可能な調査は続けます。SDK/runtime 不在は未実施であり、互換性合格ではありません。

## 2. 根拠と影響範囲

[チェックリストと公式出典](references/checklist.ja.md)を読み、アプリが使う framework の項目だけ調査します。リリースノートは更新されるため、検索要約の beta 番号を現行版と断定しません。実際のページのバージョン・確認日・関連項目と対象ファイル/シンボルを記録します。

指摘は `再現手順 → 期待/実際の動作 → 影響ファイル → 根拠 → 最小修正 → 検証` で整理します。API 変更、アプリの不具合、依存関係の問題、OS/SDK の既知の問題、環境問題を区別します。検索一致や deprecation 警告だけで置換を決めません。

| 状況 | 参照 |
|---|---|
| リリース変更をコードと再現に結び付ける | [変更マッピング](references/change-map.ja.md) |

全体移行では該当する3手順を実行します。特定エラーだけの依頼では関連参照のみ読みます。

## 3. 必要な修正

- ビルドエラーと再現する回帰を優先します。名前・シグネチャ・モジュール・availability はローカル SDK 宣言と公式資料で確認します。
- `#available` は実行 OS の分岐であり、旧 SDK にない宣言をコンパイル可能にはしません。`canImport` もモジュール内のシンボルを保証しません。旧 SDK では可能な修正を進め、未確認 API のコードを追加しません。
- deprecated API は削除時期、実際の影響、代替 API の動作差を確認します。警告を消すだけの大規模リファクタリングは行いません。
- actor isolation/Sendable エラーは呼び出し境界と所有権を修正します。無差別な `@unchecked Sendable`、`nonisolated(unsafe)`、検査無効化で隠しません。
- 依存変更は確認した問題を解決する最小範囲に限定し、lockfile 差分を確認します。Tuist などの生成ツールでは生成物より元の manifest を修正します。
- OS の既知の問題は対象 build で再現を確認します。workaround が必要なら適用条件と撤去条件を記録し、他 OS の既存動作を保ちます。
- 保存モデル・移行・認証・決済の変更では既存データと復旧を検証します。テストの都合でユーザーデータを消したり、実購入・外部送信を実行したりしません。

## 4. 検証と報告

影響 target のビルドと関連テストを実行し、利用可能な iOS 27 環境と既存の対応 OS で変更フローを確認します。新しいテストは再現した不具合や意味のある状態遷移を検証する場合に追加します。

結果は **合格 / 失敗 / 未実施 / 対象外**で記録します。静的調査、ビルド、simulator、実機の結果を分けます。最終報告には指摘・変更ファイル、根拠リンク、コマンド/環境/結果、残る制約、再検証手順を含めます。アプリソースや実行環境がなければ、スキル文書の検証をアプリ互換性の検証として報告しません。

Duo 固有の開閉・ヒンジ・複数画面も依頼された場合は、インストール済みの `iphone-duo` スキルを併用します。一般的な互換性確認は他スキルなしでも実施できるようにします。
