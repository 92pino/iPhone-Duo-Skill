# iOS 27 Migration

한국어 | [English](SKILL.en.md) | [日本語](SKILL.ja.md)

기존 앱이 iOS 27에서 정상 동작하도록 점검하고 필요한 부분을 수정한다. 가이드는 한 언어만 읽고 사용자 언어로 보고한다. 번역은 별도 스킬이 아니며 세 언어를 함께 갱신한다.

## 범위

검토 요청이면 근거와 발견 사항을 보고한다. 수정 요청이면 가능한 변경과 검증까지 완료한다. 기능 추가, 전면 UI 개편, 일괄 의존성 업데이트, 최소 지원 OS 또는 Swift 언어 모드 변경을 마이그레이션의 기본 작업으로 포함하지 않는다. 앱의 기존 지원 범위와 데이터·사용자 흐름을 유지한다.

## 1. 기준 환경 확보

- 프로젝트 지침과 작업 트리 변경을 읽고 workspace/project, scheme, 앱·extension·테스트 target, 배포 대상, 의존성 lockfile, CI 빌드 방법을 확인한다.
- `xcodebuild -version`, `xcodebuild -showsdks`, `xcrun swift --version`으로 실제 환경을 기록한다. 필요한 경우 `xcrun simctl list devices available`로 runtime과 destination을 찾는다.
- **기존 SDK로 만든 앱의 iOS 27 실행**과 **iOS 27 SDK로 재빌드한 앱의 실행**을 구분한다. SDK에 연결된 동작 변화와 OS 자체의 변화를 혼동하지 않는다. 각 결과에 Xcode/SDK/OS build를 남긴다.
- 수정 전 관련 빌드·테스트를 실행하거나 기존 CI 증거를 확보한다. 실패하면 원래 오류인지 기록하고 진행 가능한 점검을 계속한다. SDK/runtime 부재는 미실시이며 호환성 통과가 아니다.

## 2. 근거와 영향 범위 확인

[점검표와 공식 출처](references/checklist.md)를 읽고 앱이 사용하는 framework 항목만 조사한다. 릴리스 노트는 업데이트되므로 검색 요약의 beta 번호를 현재 버전으로 단정하지 않는다. 실제 페이지의 버전·확인일·관련 항목과 해당 파일/심벌을 기록한다.

각 발견 사항을 `재현 단계 → 기대/실제 동작 → 영향 파일 → 근거 → 최소 수정 → 검증`으로 정리한다. API 변경, 앱의 결함, 의존성 문제, OS/SDK 알려진 문제, 환경 문제를 구별한다. 검색 결과나 deprecation 경고만으로 교체를 결정하지 않는다.

## 상세 점검 절차

| 상황 | 참조 |
|---|---|
| 릴리스 노트의 변경을 코드·재현과 연결 | [실제 변경 매핑](references/change-map.md) |
| 이전 앱에서 업데이트 후 데이터·로그인 유지 확인 | [업데이트 설치 검증](references/upgrade-validation.md) |
| 패키지·바이너리·plugin 빌드 오류 조사 | [의존성 점검](references/dependencies.md) |

전체 마이그레이션에서는 앱에 해당하는 세 절차를 수행한다. 특정 오류만 요청받으면 관련 참조만 읽는다.

## 3. 필요한 수정

- 빌드 오류와 재현되는 회귀부터 수정한다. 이름·시그니처·모듈·availability는 로컬 SDK 선언과 공식 문서에서 확인한다.
- `#available`은 실행 OS 분기이며 구 SDK에 없는 선언을 컴파일 가능하게 만들지 않는다. `canImport`는 모듈 내부 심벌의 존재를 보장하지 않는다. 구 SDK에서는 가능한 수정만 하고 미확인 API 코드를 추가하지 않는다.
- deprecated API는 제거 시점과 실제 영향, 대체 API의 동작 차이를 확인한다. 경고 제거만을 위한 대규모 리팩터링을 하지 않는다.
- actor isolation/Sendable 오류는 호출 경계와 소유권을 고친다. 무차별적인 `@unchecked Sendable`, `nonisolated(unsafe)`, 검사 비활성화로 숨기지 않는다.
- 의존성 변경은 확인된 문제를 해결하는 최소 범위로 제한하고 lockfile 변경을 검토한다. Tuist 등 생성 도구를 쓰면 생성 파일 대신 원본 manifest를 수정한다.
- OS의 알려진 문제는 해당 build에서 재현되는지 확인한다. workaround가 필요하면 적용 조건과 제거 조건을 남기고 다른 OS에서 기존 동작을 보존한다.
- 저장 모델·마이그레이션·인증·결제 흐름 변경은 기존 데이터와 오류 복구를 검증한다. 테스트 편의를 위해 사용자 데이터를 지우거나 실제 구매·외부 전송을 실행하지 않는다.

## 4. 검증과 보고

영향받는 target의 빌드와 관련 테스트를 실행하고, 확인 가능한 iOS 27 환경과 기존 지원 OS에서 변경된 사용자 흐름을 검증한다. 새 테스트는 재현된 결함이나 상태 전환을 검증하는 경우에 추가한다.

결과는 **통과 / 실패 / 미실시 / 해당 없음**으로 기록한다. 정적 조사, 빌드, simulator, 실기기 결과를 분리한다. 최종 보고에는 발견·수정 파일, 근거 링크, 실행 명령/환경/결과, 남은 제약과 재검증 절차를 포함한다. 앱 소스나 실행 환경이 없으면 스킬 문서 검증을 앱 호환성 검증으로 보고하지 않는다.

Duo 고유의 개폐·힌지·다중 화면 문제도 요청받았다면, 설치된 `iphone-duo` 스킬을 함께 사용한다. 이 스킬의 일반 호환성 점검은 다른 스킬 없이도 완료할 수 있어야 한다.
